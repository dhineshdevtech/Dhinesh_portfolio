# Product Brief — Dhinesh Portfolio

## Product and Audience
- **Product Name:** Dhinesh — Personal Software Engineer Portfolio & Case Studies
- **What it does:** Showcases production-ready full-stack web and cross-platform Flutter mobile applications built by Dhinesh, demonstrating end-to-end engineering capabilities, architectural depth, and real shipped products.
- **Primary Audience:** Engineering hiring managers, tech recruiters, startup founders, and freelance clients evaluating Dhinesh for Web/Mobile software engineering roles or contract projects.
- **Context of Use:** Desktop, tablet, and mobile devices; typically reviewed in 1 to 3 minutes during candidate screening or discovery calls.

## User Jobs
- **Primary Job to be Done:** Quickly determine whether Dhinesh has real, production-proven experience building scalable web and mobile software.
- **Secondary Jobs:**
  - Review live deployments (Google Play Store app, live web apps, GitHub repositories).
  - Inspect architectural decisions, challenges, and impact via detailed project case studies.
  - Check technical stack fit (Flutter, React, Next.js, TypeScript, Node.js, Firebase, Supabase).
  - Easily reach out via contact form, direct email, or LinkedIn.
- **Most Important Action on Main Screen:** "View My Work" (jumping to featured projects) or "Contact".
- **How Users Know They Succeeded:** They find live verified links, readable code samples, clear project metrics, and a direct channel to connect.

## Product Truth and Constraints
- **Required Features & Flows:**
  - Multi-level project browser (Collections -> Categories -> Subcategories -> Project Case Studies).
  - Direct live links to Google Play Store and production Vercel/Firebase deployments.
  - Interactive contact form with client-side validation and quick email copy.
  - Certificates and Resume download/view flows.
- **Constraints:**
  - No fake claims or placeholder metrics.
  - Must respect privacy (no sensitive proprietary client credentials).
  - Clean local git tree; never push or mutate remote repositories without explicit consent.

## Brand Character
- **Desired Character:** Technically grounded, authentic, high-signal, clean, confident, meticulously crafted.
- **Should NOT Feel Like:**
  - A cookie-cutter AI generated template with meaningless floating glow blobs.
  - Over-decorated with nested cards, jittery hover scales, and arbitrary numbers (`01`, `02`).
  - Gimmicky or superficial.

## Success Criteria
- **Functional:** All links, navigation controls, dropdowns, case study views, and copy actions operate reliably.
- **Visual:** Cohesive visual hierarchy, high contrast, readable typography, and intentional spacing.
- **Accessibility:** Semantic HTML, full keyboard navigation with visible focus rings (`:focus-visible`), WCAG 2.2 AA contrast adherence, and `prefers-reduced-motion` compliance.
